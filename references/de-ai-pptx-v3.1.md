一、任务路由：先判断你要做哪件事
 
收到请求后先归类，三条路线的动作完全不同，混用会做无用功。
 
表2 三种任务类型与对应章节
 
| 类型 | 用户说法 | 执行路线 |
 
| --- | --- | --- |
 
| 改造 | 这份 PPT 太像 AI 做的、帮我改得像人做的 | 第五章至第九章：取证 → 拷问 → 改造 → 验收 |
 
| 体检 | 先看看这份 PPT 有没有 AI 味、打个分 | 第五章取证，输出双评分报告，不改文件 |
 
| 生成 | 帮我做一份 PPT，要求不像 AI 做的 | 第十章至第十三章：澄清 → 大纲 → 版式配方 → 素材 → 校对 |
 
若用户同时要求“重做一版更像人做的”，默认按改造处理；只有用户明确说推翻重做，才走生成路线，并把原文件的结论与数据沿用过来。
 
二、核心主张：人味来自取舍，不来自抖动
 
先说清什么不该做。随机改字号、随机拉间距、加噪点、做旧纹理，这类“伪人工抖动”只是把机器味换成伪装味。评委或审阅者看到“有人刻意打乱过”的第一反应是这份文件被动过手脚，比原始状态更容易被判定为伪造。
 
真正让人相信这是人做的只有三件事。第一，有具体的数字和人话，例如“39 元一张，一小时出 300 张”，而不是“显著提升效率”。第二，有真实证据，原始报道截图、原始数据图、可点开的来源链接、自己动手做过的实物。第三，有取舍的痕迹，这页只讲一件事、某个方向被否掉、否掉的原因与代价。证据缺失是最致命的 AI 味，优先级高于任何排版问题。
 
三、评分模型：两个分数，五层指纹
 
评分拆成两个，因为优化目标不同。取证分含元数据层，回答“会不会被查出来”，是底线；观感分不含元数据层，只统计肉眼可见的部分，这才是改造目标。两者不能合并，否则会出现清完元数据就以为完事的误判。
 
表3 五层指纹、扣分权重与改造手段
 
| 层 | 判据 | 典型指纹 | 权重 | 改造手段 |
 
| --- | --- | --- | --- | --- |
 
| L0 元数据 | 查 XML 才可见 | 作者字段为工具名或空、生成工具痕迹、异常创建时间、统计字段为 0、画幅属性与页面不符 | 16 | 清元数据、归一化统计字段、修正画幅属性 |
 
| L1 渲染 | 肉眼可见 | 中文字体槽绑西文字体导致掉字形、字面项目符号、自动缩放属性、语言标注在中文与英文间乱跳 | 14 | 三槽字体同写、缩放归一、按内容语言标注 |
 
| L2 文案 | 读完就有感觉 | 从 A 到 B、不要 A 要 B、冒号分论、动宾堆叠、AI 高频词、要点等长 | 25 | 标题重写、词库替换、节奏打散 |
 
| L3 证据 | 读完发现没真东西 | 零图片、零讲稿、无署名、无方法论页、假引用链接 | 20 | 补讲稿与署名、插真实截图配出处、修链接 |
 
| L4 风格 | 说不出哪里怪就是假 | 卡片全页等高、每页元素数一致、满页项目符号、无结论条 | 25 | 人工改几何、每页补结论条 |
 
权重按百分制分配，取证分等于五层合计；观感分等于渲染、文案、证据、风格四层合计。判定阈值：观感分十以内视为通过，二十以内可接受，三十以上必须重做。这些数值是校准起点，允许按实际评审口径调整，但一旦选定就要在同一批文件里保持一致，否则分数不可比。
 
（一）六项必须量化的判定规则
 
字号按用途分桶统计：正文、表格正文、项目符号、标签、脚注页码、标题各算各的。全局最小字号不等于正文字号，只看最小值必然误判。
 
字体槽检查看三处：西文槽、东亚槽、复杂文本槽。中文 run 的东亚槽若绑定西文字体，渲染时会掉字形，这是最典型的机器痕迹。
 
自动缩放属性只认一种：文本框应使用固定缩放比例属性，凡出现“随文本自动调整形状高度”的，一律记为渲染层问题。
 
语言标注：中文 run 标 zh-CN，纯西文 run 标 en-US。乱跳会导致拼写检查、字体回退、输入法全部跑偏。
 
项目符号：正文里手打的圆点、方块、短横线一律记为文案层问题，应改为原生编号或原生项目符号。
 
链接审计：锚文本点名的来源与目标域名不一致即为假引用。假引用比排版问题更致命，必须逐条核对。
 
（二）密度与时长的硬公式
 
被要求“再专业一点、再详细一点”时，先算这笔账：页数乘以每页正文字数，除以每分钟一百六十五字，就是讲述分钟数。超出答辩或汇报时长就拆页，不要靠缩字号解决。
 
实例：十页、正文三千七百一十七字，按公式需要二十二点五分钟，而答辩只有八分钟，超出近三倍。这个矛盾比字号、配色都致命，但它不在排版维度上，必须单列为决策分支处理。
 
四、五阶段流水线：顺序不可交换
 
表5 阶段、输入输出与阻断条件
 
| 阶段 | 输入 | 输出 | 阻断 |
 
| --- | --- | --- | --- |
 
| Phase 0 合规闸门 | 文件、规则条款、署名权归属 | 允许做什么、不许做什么 | 是：结论不允许则整条流程停止 |
 
| Phase 1 取证 | 原文件 | 双评分、五层指纹、事实清单 | 否 |
 
| Phase 2 拷问 | 文件与事实清单 | 决策锁定摘要、未决问题清单 | 是：未锁定不得开始改造 |
 
| Phase 3 改造 | 锁定摘要与改造计划 | 改造版文件 | 否 |
 
| Phase 4 验收 | 改造后文件 | 复扫报告、预览、资产核对 | 否：不达标则回退返工 |
 
顺序的理由：取证在前，否则拷问会去问文件里早就写着的事实，浪费回合；拷问在前，改造是昂贵动作，页序重排、页码重写、图表重挂，基于未确认假设改一遍再返工的代价远高于问清楚；改造内部则是机械层先于版式层，脚本秒级完成的部分先做，避免后续加页把页码与结论条位置全部再动一遍。
 
五、Phase 0 · 合规闸门
 
任何文件读写之前完成，不可跳过，也不替用户判断。规则是用户的责任。
 
表6 合规闸门的三个确认项
 
| 确认项 | 要问清什么 | 不通过时 |
 
| --- | --- | --- |
 
| 署名权 | 文件里的数据、结论、截图，你是否愿意承担 | 停止，先划清可改造素材范围 |
 
| 规则条款 | 章程或考核办法中关于 AI 辅助、AI 代做的原文怎么写的 | 停止，拿到原文条款再定改造边界 |
 
| 用途 | 课堂作业、比赛评审，还是对外发布 | 对外发布需额外做脱敏处理 |
 
闸门通过后写一句结论存档，例如“允许 AI 辅助润色，不允许代做，因此不改任何原始数字”。后续每一条改动都要能追溯到这类结论。
 
六、Phase 1 · 取证
 
取证全部由 agent 用 python-pptx 读取后本地计算，不联网、不调用外部服务。按下列顺序执行，把结果写入一份取证记录。
 
（一）元数据层检查
 
读 core_properties 的 author、last_modified_by、comments、keywords、revision，读文档属性包中的应用信息与统计字段，读页面尺寸与画幅属性。凡作者为空或为工具名、创建时间异常、统计页数字段为 0 或与实际页数不符、画幅属性与页面尺寸矛盾的，逐条记录。
 
（二）渲染层检查
 
遍历每一页的每个形状，再遍历文本框架内每个段落的每个 run，读字体槽、字号、粗体、斜体与语言属性；读文本框的自动缩放设置；统计字面项目符号出现的次数。运行结果按“用途分桶”聚合字号，输出每桶的字号分布与占比最多的字号。
 
（三）文案层检查
 
抽取所有标题与正文段落，按下节词表做命中统计；统计每页要点条数与要点字数，计算同页要点长度的离散程度，长度高度一致即为机器排比；统计冒号分论、动宾堆叠、引号使用率。
 
（四）证据与风格层检查
 
统计图片数量、讲稿备注覆盖率、是否存在目录页与方法论页、是否存在署名信息；抽取全部外部超链接，逐个比对其锚文本所指机构与目标域名是否一致；统计每页形状数量与高度分布，卡片刻度整齐划一即为风格层问题。
 
（五）输出格式
 
取证记录建议字段：ai_flavor_score / visible_score / breakdown 五层 / font_size_by_usage 分桶 / hyperlink_audit 列表 / placeholder_list 待补项
 
取证只出报告，不动文件。用户若只要体检，到此结束。
 
七、Phase 2 · 拷问：只有九件事必须问人
 
文件里查得到的事实不许问人，这是硬规则。拷问只解决九类只有人能决定的节点，按依赖分轮，一轮只问当前可以问的一圈，问完停下等回答。
 
表7 九类决策分支
 
| 编号 | 决策内容 | 优先级 | 依赖 |
 
| --- | --- | --- | --- |
 
| B01 | 合规：署名权、AI 辅助边界、规则条款 | 阻断 | 无 |
 
| B02 | 身份：姓名、院校、班级、队名、指导教师、日期 | 阻断 | B01 |
 
| B03 | 范围：只改表现层，还是连内容一起重构 | 核心 | B01 |
 
| B04 | 时长与密度：汇报时长、密度与时长如何取舍 | 核心 | B03 |
 
| B05 | 结构与拆页：目录、方法论、问答页，哪几页要拆 | 核心 | B03、B02 |
 
| B06 | 文案：标题落到哪个具体数字、词库怎么换 | 核心 | B03 |
 
| B07 | 证据：哪几页补截图，补不到如何降级结论 | 核心 | B03 |
 
| B08 | 链接：假引用怎么修，无原文来源怎么写 | 核心 | B03 |
 
| B09 | 版式：配色保不保、卡片与密度打不打散 | 润色 | B03 |
 
分轮示例：第一轮只问 B01；第二轮问 B02 与 B03；第三轮再问 B04 至 B09。范围没锁定就问后面的问题，等于替用户做了范围决策，属于披着问号的猜测。
 
（一）六种强制性问题模板
 
为什么选这个而不选替代方案：例如“为什么保留原配色而不换成更常见的蓝灰，判据是什么”。
 
杀手准则：例如“什么现象出现时，你会认为去 AI 味这条路走错了”。
 
阻塞点：例如“哪些页你自己也没底，缺的是数据、经历，还是判断”。
 
取舍哪一边：例如“信息密度和讲述时长，你保哪个，答辩实际几分钟”。
 
依赖确认：例如“署名定了吗，没定的话封面、目录、页码都要等它”。
 
六成把握：例如“就算查不到原文链接，这些假引用你现在打算怎么处理”。
 
每题必须附一条推荐答案和一句理由。推荐答案是给用户的锚，让他知道好答案长什么样，同时暴露你的偏见，说错了他可以直接反驳。
 
（二）必须替换掉的软问题
 
“你确定吗”改成“为什么这条而不那条”。
 
“你考虑过吗”改成“决定性约束是什么”。
 
“如果失败了怎么办”改成“什么会让你认为这条路是错的”。
 
“能展开说说吗”改成点名具体缺口。
 
“有什么问题吗”改成逐个点名，不要打包。
 
（三）停止条件
 
满足任一即停：所有分支都有明确答案，没有一条被静默假设；连续三个回答没有产生新分支；已经能预判下一个答案；用户喊停；决策可逆且改回来只要五分钟，此时继续拷问的成本已高于犯错成本。
 
（四）决策锁定摘要模板
 
决策锁定：1 [B01] 合规结论 → 因此不改原始数据；2 [B02] 署名各项由谁填写；3 [B03] 范围：只改表现层
 
明确不在范围内：不换配色体系、不新增无出处配图、不改数据口径
 
待用户补齐：封面署名几项、某页调研过程、讲稿定稿
 
摘要是产物，拷问过程是消耗品。后续每条改动都要能追溯到其中一条，追溯不到的就是夹带。
 
（五）grill-me 协议：四条硬规则
 
这套拷问机制来自开源技能 grill-me，原名就是“把我拷问一遍”。它的核心不是多问几个问题，而是把决策画成一棵设计树：每个决定都向下挂着一串依赖它的子决定。四条硬规则决定了它跟普通提问的区别。
 
第一条，按轮推进。把前提已经确定、现在就能问的决定组成一个前沿集合，一轮把整个前沿问完，编好号、每题附上推荐答案，然后停下来等回答。等回答再算下一轮，不能一口气问完十个问题，那样用户只会回答最容易的那个。
 
第二条，每个问题必须带推荐答案。推荐答案的作用有两个：让用户知道好答案长什么样，同时把你的偏见暴露出来，说错了用户可以直接反驳。措辞上有一个细节要求，题干要写成“是”即等于接受推荐答案，这样用户答一个字就能推进。
 
第三条，查事实是你的活，不是用户的活。凡是能从文件、环境、工具里查到的事实，一律自己查，不许问用户。需要跨文件核查时可以并行派出独立的检索任务，别让整轮提问卡在它上面：正在查的事实是一条尚未确定的前提，只有依赖它的下游问题需要等，其余前沿问题照常问。
 
第四条，对齐优先于产出。前沿没清空之前不许动手改文件，也不许按假设先改一版。用户的决定是用户的责任，你的责任是把它们一个个摆到桌面上。
 
（六）一轮提问的写法
 
每轮按统一格式输出，编号、标题、题干、推荐答案四件齐全，题目之间加分隔线。题干可以多段，可以把选项直接列出来。
 
Q1 - 封面署名：封面、目录、致谢页要用的署名信息具体是什么？缺的几项是还没决定，还是这一版不写？
 
推荐答案：姓名、院校、专业班级、队名、指导教师、日期，逐项给出；指导教师拿不准就留空，空着是缺信息，编上是造事实。
 
理由：署名是审阅者十秒内能查到的硬伤，缺一栏比多一栏更扎眼。
 
如果某题的回答依赖本轮另一个还没回答的问题，它属于下一轮，不属于这一轮。把这类问题硬塞进当前轮，等于逼用户在信息不全时下判断。
 
（七）事实与决策的分界线
 
这条线必须划清楚，否则拷问会退化成闲聊。文件里有的，例如页数、图片数量、字号分布、外链条数、是否已有目录页，全部由取证阶段读出来，不进入提问。文件里没有的，例如署名、真实经历、答辩时长、某个方向为什么被否掉、能接受多大改动，只能问人。
 
判断方法很简单：这个问题我能不能用工具查到答案。能查到就去查，查不到才问。提问时把已经查到的事实一并写进题干，例如“已知全篇未出现任何署名关键词”，既证明做过功课，也把问题限定在人身上。
 
（八）什么时候算问完
 
前沿清空就算完成，也就是每个分支都有明确答案，没有任何一条被静默假设。此外还有四条可以提前收手的判据：连续三个回答没有产生新分支；已经能预判下一个答案；用户明确喊停；决策可逆且改回来只要几分钟。
 
最后一句话必须由用户说。在用户确认“我们已经对齐”之前，不许开始改造。确认之后先落一份决策锁定摘要，再动手。
 
八、Phase 3 · 改造：五层逐级处理
 
（一）元数据层
 
清空作者与最后修改者、描述、关键词、修订号；按实际时间重写创建时间；补齐统计字段中的页数与字数；按真实页面尺寸修正画幅属性。改完确认统计字段与实际一致。
 
（二）渲染层
 
字体三槽同写：西文槽、东亚槽、复杂文本槽全部显式写入。中文字体统一为微软雅黑或思源黑体，纯西文统一为 Arial；清除指向 Noto 等非常用字体的引用；中文 run 一律标 zh-CN，纯西文标 en-US。自动缩放改为固定缩放比例，常用 92%，改完必须重新排版检查是否溢出。
 
（三）文案层
 
标题落地到具体数字或具体对象，避免抽象拔高。AI 高频词替换为更具体的同义词，例如“工作流”改为“交付流程”，“赋能”改为具体动作。要点节奏打散，同页要点长度不要一致，每页补一条结论条，把本页结论放在页眉下方或页脚上方一行。
 
表8 AI 高频词与替换方向
 
| 高频表达 | 问题 | 替换方向 |
 
| --- | --- | --- |
 
| 从 A 到 B / 不要 A 要 B | 句式模板化，无信息增量 | 改成具体动作与结果，带数字 |
 
| 赋能、闭环、抓手、生态 | 抽象名词堆叠 | 换成可验证的动作或对象 |
 
| 显著提升、大幅优化 | 无口径的形容词 | 给出对比基线、幅度与时间范围 |
 
| 冒号分论：三大要点：一是…… | 排比腔，读起来像机器 | 拆成短句，或直接给结论加数据 |
 
| 每页要点长度相同 | 刻意对齐的机器痕迹 | 长短交错，重要的一条单独成行 |
 
（四）证据层
 
先修链接：锚文本写“某媒体”但指向另一家域名的，要么改正域名，要么删掉改写成“据公开报道，未能核实原始链接”。再补证据：能拿到原始截图、原始数据表、自己做的实物照片的页优先补，补不到的页把结论强度下调，改为“初步判断”“待进一步验证”，不允许保留“权威数据显示”这类无法兑现的表述。最后补讲稿备注、目录页、方法论页、署名块。
 
（五）风格层
 
这一层脚本不做，必须人工改几何。三件事：卡片高度自适应内容，不要全页等高；每页元素数量刻意不等，避免每页都是四宫格；满页项目符号的页面改成结论加三条支撑的版式。改完再看一遍，判断标准是“说不出哪里对，但明显不像模板”。
 
九、Phase 4 · 验收：四项硬指标
 
表9 验收项与通过标准
 
| 验收项 | 方法 | 通过标准 |
 
| --- | --- | --- |
 
| 观感分 | 用同一套规则复扫 | 显著下降，且没有新增“像人但经不起追问”的空壳 |
 
| 资产完整性 | 改前记录图表数、嵌入表格数、外链数，改后比对 | 数量完全一致 |
 
| 渲染目视 | 逐页看：文字溢出、元素挤压、图表变形 | 无溢出、无遮挡、图表不变形 |
 
| 待补清单 | 统计待填标记数量 | 越少越好；清单长说明拷问没做够，回去补 |
 
资产零丢失是改造最常见的翻车点。读写过程中，原生图表、嵌入表格、指向外部来源的超链接都可能丢失或错位，所以必须在动手前记录原值，而不是改完才去检查还有没有。
 
失败处理：改造后文字溢出，把固定缩放比例降到百分之八十五至九十二，或减少该页字数；评分没降，回看取证报告确认是哪一层没动，多数情况是证据层和风格层没做；检测不到任何 AI 痕迹，可能文件本来就是人工做的，先与用户确认，不要为了改而改。
 
十、红线：六条不许越过的线
 
不伪造个人经历、调研过程、数据、来源、图片与截图。无法核验的一律留待填，由用户补真实内容。
 
不删来源超链接。链接是可信度资产，删掉反而更像伪造。
 
不改原始数据。要改口径就明确标注口径。
 
不做伪人工抖动。随机字号、随机间距、噪点、做旧纹理都属于伪造痕迹，比不改更糟。
 
不在拷问期间动手改文件。对齐优先于产出。
 
赛事与考核规则优先。正当用途是把 AI 草稿变成自己真正参与、并且能答辩的作品。
 
十一、生成模式：从零做一份不像 AI 的 PPT
 
如果用户不是改造而是新建，走这条路线。七步顺序不要调换，后面每步都依赖前面的决定。

| --- | --- | --- |
 
| 第一步 | 确定交付形态与信息密度 | PPTX 还是网页；演讲型还是阅读型 |
 
| 第二步 | 七问澄清 | 风格、受众、时长、素材、图片、配色、硬约束齐全 |

（一）七问澄清清单
 
风格基调：编辑杂志风、瑞士网格风，还是指定某套主题色。
 
受众与场合：内部汇报、对外发布、课堂培训、高管评审。
 
时长与页数：十五分钟约十页，三十分钟约二十页，四十五分钟约二十五至三十页。
 
原始素材：有无文档、数据、旧文件、文章链接。
 
图片与截图：现有图片怎么处理，是否需要重生成。
 
主题色：品牌色还是从预设里选。
 
硬约束：必须出现的数据、不能出现的表述。
 
（二）信息密度两档
 
演讲型低密度：一页一个观点，大字、强层次、多留白，每页最多一到三条要点，宁可多分页。阅读型高密度：页面要自足，用网格、表格、注释承载信息，每页四到八条要点或四到六张卡片。内容超出当前档位就拆页，不要缩字号硬塞。
 
（三）文案与讲稿
 
没有思路时，提示词写清五件事：场合、身份、对象、目标、页数与时长。示例：申请晋升为市场运营主管的季度汇报，十五分钟，十至十五页。
 
有底稿时先指定结构：复盘用金字塔，方案用情境冲突问题答案，演讲用钩子定调主体转折收束。
 
要口头讲解就同步写逐字稿：每页一百五十至三百字，对应两到三分钟；关键词加粗，过渡句单独成段；按口语写，不要写成书面文章。
 
十二、内置视觉配方：无需任何模板文件
 
不允许联网、也没有现成模板时，用下面三套配方直接从零建立版式。参数都是可执行的：页面十三点三三乘七点五英寸，安全边距上下左右各零点六英寸，正文最小不低于十六磅，标题二十八至四十磅。

（一）执行要点
 
同一套配方内，同级标题与同级正文的字号、字重、颜色必须全篇一致，不一致比难看更容易被识别。
 
每页至少留一处明显留白，不要四边填满；四边填满是最典型的机器排版。
 
配色不超过三色：底色、正文色、一个强调色。强调色只用于结论条、关键数字、章节号。
 
卡片高度按内容自适应，同页卡片不要全部等高；连续三页版式相同的，改掉其中一页。
 
避开被用滥的字体与配色：不要 Arial、Inter、Roboto 与系统默认，不要白底紫色渐变。英文稿同样适用：不用 Arial、Inter、Roboto、Helvetica 默认值，英文字体按 SKILL.md 的 English / Latin Font Pairing Extension 按风格与角色搭配（标题衬线／正文／数字等宽各司其职，全篇三至四套以内）。
 
动效只加在字少图大的页面，例如封面、章节页、单图页；信息密集页加动画会干扰阅读。判断标准是去掉动画后信息是否受损。
 
（二）素材处理三种方法
 
标题生图：从标题提取关键词，提示词写成风格关键词加主体画面加场景描述。示例：真实摄影风格，广阔海面上巨大涌浪正在形成，一名穿黑色泳衣的冲浪者位于浪尖。
 
草图控制：先在版面上用形状画出时间轴波浪线、矩阵方块、金字塔轮廓，截图后据此生成背景图，避免图与版式两张皮。
 
主体精修：对质量差的素材做定向处理，去背景、换场景、产品转白底图，再与场景合成。
 
若生成图片的能力不可用，改用纯形状方案：用圆角矩形加纯色块承载主视觉，用线条与数字做信息图，用原生图表替代配图。宁可少图，也不要塞风格不统一的网络图片。
 
（三）素材校验五个检查项
 
图片数量是否满足版式槽位；画幅是否与槽位一致、能否居中裁切；方向是否与版面匹配；明暗是否与文字对比充足，黑字压图要亮图、深色版式要暗图；是否满足特殊前提，例如只接受白底图或透明背景。三档结论：可以开工、可以开工但须先与用户确认问题、不要硬做先补素材。
 
十三、提示词模板库：可直接复制
 
（一）生成整份 PPT 的指令
 
请按以下约束制作一份 N 页 PPT：用途为【场合】，我是【身份】，听众是【对象】，目标是【要达成的结果】，讲解时长【分钟】。结构用【金字塔/情境冲突问题答案/钩子定调主体转折收束】。视觉用【商务简约/编辑杂志/瑞士网格】配方，配色【主色】，避免白底紫渐变与被用滥的字体。每页只讲一件事，正文不少于十六磅。先给三张封面预览让我选，定稿后再生成全部页面。
 
（二）改造单页文案的指令
 
把这一页的标题改成带具体数字或具体对象的表述，不要抽象拔高；把要点改成长短不一的短句，去掉冒号分论与排比；补一行本页结论；不要新增原文没有的数据，缺数据的地方写待补。
 
（三）拷问单轮的指令
 
只问当前可以问的一组问题，每题附推荐答案与一句理由；不要问文件里写着的页数、图片数量这类事实；问完停下来等我回答，不要顺手改文件。
 
（四）验收自查的指令
 
按五层指纹复扫这份文件，逐层给出问题清单与分数变化；核对图表、嵌入表格、外链数量是否与改前一致；列出仍待填的位置。

十五、一句话总结
 
这份技能的全部价值，是把“像不像人做的”拆成可执行的顺序：先过合规闸门，再取证打分，把只有人能决定的事问清楚，然后从机械层改到版式层，最后用同一套规则复扫验收。任何一个环节跳过，出来的都只是更精致的模板，而不是你的作品。
